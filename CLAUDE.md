
# Правила для агента

Проект: игра «Накорми зверей» на Godot 4.7 (GDScript) для Яндекс Игр, веб-билд, в основном телефоны.

- Краткий план и список шагов: `PLAN.md`.
- Подробные задачи: `tasks/`.
- Справочники: `reference/`.
- Нерешённые вопросы: `OPEN_QUESTIONS.md`.
- Выполненные шаги и журнал: `PROGRESS.md`.

## Главные правила

1. **Говори с пользователем только по-русски**: ответы, отчёты, вопросы, объяснения ошибок. Имена в коде на английском, комментарии в коде на русском.
Когда пользователь пишет «фиксируй»:
1. Проверить git status.
2. Обновить docs/PROGRESS.md.
3. Добавить только файлы текущего этапа и docs/PROGRESS.md.
4. Создать коммит.
5. Выполнить git push origin main.
6. Проверить git status и git log origin/main..HEAD.
7. Сообщить пользователю хеш коммита и результат отправки на GitHub.
При конфликте локальная версия должна перезаписывать удалённую версию в репрозитории, при необходимости выполняй принудительный push и сообщи пользователю. Без слова «фиксируй» push не делай.
3. **Работай строго по одному шагу.** Пользователь пишет «Выполни T11c». Выполняй только эту задачу. Не начинай следующие шаги и не добавляй улучшения вне задачи.
4. Не удаляй и не переписывай файлы пользователя без просьбы. Файлы спецификаций `PLAN.md`, `tasks/`, `reference/` и `OPEN_QUESTIONS.md` не редактируй без прямой просьбы пользователя. В `PROGRESS.md` меняй только отметки выполнения и «Журнал».

## Каркас: не ломать

Каркас: `autoload/ya.gd`, `autoload/save.gd`, `autoload/loc.gd`, `web/shell.html`, `export_presets.cfg`, `project.godot` (рендер, существующие автозагрузки), `tools/`.

- Менять каркас можно только там, где шаг прямо разрешает (например, добавить ключи в `Loc.T`, поля в `Save.DEFAULTS`, строку в `[autoload]`). Иначе остановись и объясни, зачем нужна правка.
- Весь доступ к SDK только через `Ya`. `JavaScriptBridge` разрешён только в `autoload/ya.gd`, слова `YaGames` и `ysdk` только в `web/shell.html`. Новые возможности SDK не придумывай по памяти: найди актуальную документацию Яндекса и добавь по образцу (JS-мост, затем `Ya._on_js_event`, затем метод `Ya` с заглушкой для редактора).
- Порядок старта: `await Ya.initialize()`, `await Save.load_all()`, `Game.start()` (после T03), `Ya.loading_ready()`, `Ya.gameplay_start()`.
- Новые автозагрузки не добавляй, кроме `Game` в шаге T03.

## Как пользоваться каркасом

```gdscript
Ya.show_interstitial()                      # только в паузах; частоту ограничивает сам Ya
Ya.show_rewarded(func(): ...)               # награда только внутри колбэка, по кнопке игрока
Ya.gameplay_start() / Ya.gameplay_stop()    # когда игра идёт / на паузе, в меню, в окнах
Ya.submit_score("имя_лидерборда", число)
Save.data["поле"]; Save.save_data()         # поля описаны в Save.DEFAULTS, сохранять по событиям
Loc.t("ключ")                               # тексты в Loc.T, минимум ru и en
```

Во время рекламы дерево сцены на паузе и звук выключен. Не ставь `process_mode = ALWAYS` на игровую логику. Вне Яндекса (редактор) `Ya` работает заглушкой: реклама имитируется, награда выдаётся сразу.

## Правила кода и платформы

- Рендерер только `gl_compatibility`, веб без потоков. Нельзя: `Thread`, `Semaphore`, `OS.execute`, `OS.delay_msec`, GDExtension, C#. `get_tree().quit()` в вебе ничего не делает. Плагины и библиотеки без согласия не добавлять.
- Типизация везде, где можно. `snake_case` для функций и переменных, `PascalCase` для классов и узлов, `UPPER_SNAKE` для констант. Связь через сигналы, узлы через `@onready`, без длинных `get_node("../../...")`. Один файл, одна ответственность.
- В `_process` нет создания объектов. Повторно используй (пул).
- Видимый текст только через `Loc.t("ключ")`, ключи в `Loc.T` на ru и en. Хардкод строк в интерфейсе запрещён. При `Loc.language_changed` тексты обновляются.
- Сохранения только через `Save`: только JSON-типы (int, float, String, bool, Array, Dictionary). После загрузки числа в массивах приходят как `float`, приводи `int(...)`. Не сохраняй каждый кадр. Поля не удалять и не переименовывать без миграции.
- Числа и таблицы баланса лежат в `scripts/data/`, формулы в `scripts/logic/` (без узлов), сцены только отображают. Нигде больше эти числа не дублируются.
- Реклама: rewarded только по явной кнопке игрока, interstitial только в естественных паузах (не на старте, не посреди действия, не сразу после rewarded).
- Не угадывай API Godot, если не уверен в имени или сигнатуре: проверь в документации Godot 4 (поиск в вебе) или в уже написанном рабочем коде. Не смог проверить, так и скажи в отчёте.

## Мобильность

- Основной сценарий: телефон, один палец. Кнопки не меньше 64x64 пикселя в базовом разрешении 1280x720. Нет hover, правой кнопки мыши и клавиатуры как единственного способа что-то сделать.
- Интерфейс на `Control` с якорями и контейнерами, не абсолютными координатами.
- Игровые действия через собственный `InputRouter` (шаг T07), в `project.godot` действия не добавлять, создавать в коде через `InputMap.add_action`.

## Правила для 3D (в проекте включено: `docs/budget.json`, `allow_3d`)

- Тени выключены. Один `DirectionalLight3D` и мягкий окружающий свет через `WorldEnvironment`, туман можно. Нельзя `OmniLight3D`, `SpotLight3D`, SSAO, SSR, SDFGI, объёмный туман, glow, `GPUParticles3D` (только небольшие `CPUParticles3D`) и `ShaderMaterial` без явной просьбы.
- Мир из примитивов, один материал на цвет. Повторяющиеся предметы (больше десятка) через `MultiMeshInstance3D`. В кадре не больше 100 `MeshInstance3D` и около 150 тысяч треугольников.
- Звери (T24d/T24f): три режима. Режим А это один `MeshInstance3D` на зверя (запасной, по умолчанию в руках). «Лёгкий» режим для зверей загона: не больше 3 `MeshInstance3D` на зверя (корпус и две пары ног, у безногих корпус и две части волны). «Полный» режим: до 12 `MeshInstance3D`, только один такой зверь в кадре (экран получения). Лимит 100 `MeshInstance3D` в кадре действует и на загон: 20 зверей по 3 части это 60. Мир и звери в сумме не должны его превышать. Один материал на зверя, меши строятся один раз при показе, не в `_process`.
- Модели `.glb`: один материал, текстура не больше 512x512, до 3000-5000 треугольников, загружать по требованию через `ResourceLoader`. Нет файла модели, показывай заглушку из примитива, а не ошибку.
- Физику не используй, если можно обойтись: движение и границы кодом по `delta`.
- Закрытым окнам и неиспользуемым объектам выключай обработку (`set_process(false)`) или убирай из дерева.
- Картинки: lossy WebP там, где можно. Звук: OGG, музыка с низким битрейтом.

## 9. Итоговый отчёт

Короткий, в таком виде:

1. **Что сделано.**
2. **Изменённые файлы.**
3. **Что проверено** (команды и фактические результаты) и **что не проверено**.
4. **Что осталось или вызывает сомнения.** Если ничего, напиши «нет».
5. **Что пользователю стоит посмотреть самому.**

Задача считается законченной только тогда, когда сделано то, что просили, ничего лишнего не сломано, проверки выполнены, а отчёт совпадает с реальными действиями. Если одно из условий не выполнено, так и пиши.

Когда закончил задачу или остановился с вопросом, последним действием выполни `powershell -ExecutionPolicy Bypass -File tools\notify.ps1 "Готово: <название задачи>"`. Кроме этого и команд git push/git pull по слову «фиксируй», код и скрипты в сеть не обращаются
