# B10 — Выпуск

Запуск: `Выполни B10 для биома <id>`. Паспорт: `docs/biomes/NN_<id>.md`. Требуется B9.
Прочитай `docs/tasks/release/_RULES.md`, `docs/tasks/release/T72.md`, `docs/reference/R7_YANDEX.md`.

## Шаги
1. Увеличь версию игры (как в T72, шаг 6).
2. `python tools/build.py`. Размер сравни с прошлой сборкой и с лимитом из `R7_YANDEX.md`. Если больше лимита — `СТОП`.
3. Напиши тексты анонса нового биома ru/en (3–5 предложений каждый: название, что нового — звери, еда, турник, питомец). Положи в `docs/store/RELEASE_NOTES.md`.
4. После слова «фиксируй» — коммит `Биом <N>: <Название>`.
5. Скажи владельцу: загрузить сборку в консоль, отправить на модерацию. **После одобрения модерации** владелец ставит флаг `zones_open` на 1 больше (например 6). Агент флаг не меняет.
6. Запиши в `docs/PROGRESS.md`: дата, версия, размер, что выпущено.
7. **Через 1–2 дня после релиза** владелец присылает метрики (T66: `metrics_zone_enter_s` из тестового сохранения или цифры из консоли). Агент сравнивает фактическое время входа в биом с целью из паспорта (B2). Если расхождение больше 20 % — предложи изменить **только флаги** (`xp_mult`, `offline_rate`), не данные. Решает владелец.

## Что не делать
Не менять данные биомов 1–N после выпуска. Не менять `zones_open` самостоятельно.

## Тебе проверить
1. Новый биом открылся после смены флага; игроки старых сохранений видят его.

**Готово, когда:** сборка загружена, модерация пройдена, флаг поднят, запись в журнале сделана.
