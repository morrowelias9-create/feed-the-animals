# B0 — Подготовка кода к 20 биомам (один раз, до биома № 6)

Прочитай `docs/tasks/release/_RULES.md`, `CLAUDE.md`, `docs/PROGRESS.md`, `docs/reference/R11_NEW_BIOME.md`. Задачи T57 (дамп данных `python tools/dump_data.py`) и T62 (ограничитель биомов) должны быть выполнены. `autoload/save.gd` здесь можно менять только расширением массивов миграцией.

**Зачем.** Код написан под 5 биомов. Чтобы добавлять биомы по одному, число биомов должно браться из данных, а не из зашитой пятёрки.

Выполняй части 1–6 по порядку. После каждой части запускай проверки из `_RULES.md`.

## Часть 1. Убери «зашитое число 5»
1. Выполни `grep -rnE "range\(5\)|== 5|< 5|<= 5|> 5|>= 5|% 5|\[5\]|\b5 (биом|зон)" scripts tools --include=*.gd --include=*.py` и `grep -rn "CORRIDOR_LEN\|CameraRig\|FAR" scripts --include=*.gd`.
2. Для **каждой** находки реши, относится ли пятёрка к числу биомов. Составь таблицу в отчёте: «файл:строка — относится / не относится — что сделал».
3. Там, где относится: замени на `ZoneData.count()`. В `tools/*.py` бери число зон из `tools/data_dump.json`.
4. Проверь отдельно: `CORRIDOR_LEN` (длина коридора считается от границ последней зоны), `CameraRig.FAR` (дальность камеры должна позволять видеть дальние зоны, но не строить все 20), `ThrowScale`, вкладки Индекса, питомцы, тесты, `check_*.py`, `sim_progress.py`.
5. Тест: временно (в тесте, не в коде) добавь в данные 6-й фиктивный биом и убедись, что мир, Индекс, шкала не падают. Фиктивный биом после теста убери.

## Часть 2. Формат чисел `NumFmt`
Сейчас формат доходит до Dc (1e33). База дохода растёт ×40 на биом: у биома 20 она около 2,7e30 до рангов, мутаций и размеров, значит игра выйдет за 1e33.

**СТОП: спроси владельца:** «Как решить проблему больших чисел? A) продлить названия до 1e63 (рекомендую: проще и безопасно), B) смягчить рост ×40 для биомов после пятого».

- Вариант A: добавь суффиксы после Dc: `Ud` (1e36), `Dd` (1e39), `Td` (1e42), `Qad` (1e45), `Qid` (1e48), `Sxd` (1e51), `Spd` (1e54), `Ocd` (1e57), `Nod` (1e60), `Vg` (1e63). Для значений ≥ 1e66 используй научную запись `1.23e66`. Добавь тесты формата на границах: 999, 1000, 1e6, 1e33, 1e36, 9.99e62, 1e63, 1e66.
- Вариант B: изменение шага роста — не делай сам, `СТОП`, выясни у владельца новый шаг и правило для `R11_NEW_BIOME.md`.

## Часть 3. Интерфейс на 20 биомов
1. `ThrowMeter`: минимальная ширина сегмента шкалы при 20 биомах. Проверь, что сегмент не уже 8 пикселей (на экране 360 пикселей шириной); если уже — шкала показывает только соседние биомы или прокручивается. Напиши в отчёте, что выбрал.
2. Вкладки Индекса прокручиваются по горизонтали, когда не помещаются.
3. `WorldLayout`: места постаментов питомцев растут вдоль аллеи; формула позиции не упирается в число 5.

## Часть 4. Ленивый декор
Коридор 20 биомов около 9000 м. Декор строится только для зоны игрока и ±1 соседней, остальные зоны без декора (см. T67, шаг «Ленивый декор»). Если уже сделано в T67 — просто проверь и запиши.

## Часть 5. Инструменты

### `tools/check_biome.py <id>`
Читает `tools/data_dump.json` (после `dump_data.gd`) и проверяет биом по id. Печатает ✅/❌ по каждому пункту, при любом ❌ завершается с кодом 1:
- 8 зверей биома с рангами 1–8 без пропусков и повторов;
- 3 вида еды с `aim_rank` 2, 5, 8;
- 6 имён мини-зон;
- для каждого зверя: рецепт в `scripts/data/recipes/<id>.gd` и иконка `assets/ui/icons/animal_<animal_id>.png`;
- для каждой еды: рецепт в `food_recipes.gd` и иконка `food_<id>.png`;
- иконка зоны `zone_<id>.png`, текстура `ground_<id>`;
- турник биома в `UpgradeData.BARS`;
- питомец в `PetData`, его зверь — ранга 8 из этого биома;
- длины массивов по биому совпадают (звери, еда, мини-зоны);
- ключи `Loc` (название биома, звери, еда, турник, мини-зоны, питомец) на ru и en.

### `tools/new_biome.py <id> <N>`
Создаёт `docs/biomes/NN_<id>.md` (`NN` — номер из двух цифр, например `06`) копированием `docs/biomes/_TEMPLATE.md` с подставленными номером и id. Если файл уже есть — ошибка «уже существует». Добавляет в `docs/PROGRESS.md` строки B1–B10 для этого биома со статусом ⬜ в формате существующего чеклиста.

## Часть 6. Правила на будущее
Проверь, что в `docs/reference/R11_NEW_BIOME.md` и `CLAUDE.md` есть раздел «Правила после релиза» (данные биомов не меняются, миграции сохранений). Если в `CLAUDE.md` нет — добавь ссылку на `R11`.

## Проверка
Все проверки из `_RULES.md`, тесты `NumFmt`, тест с фиктивным биомом, `python tools/new_biome.py test_biome 99` создаёт `docs/biomes/99_test_biome.md` (потом удали файл и строки из `docs/PROGRESS.md`), `python tools/check_biome.py` на любом из пяти существующих биомов проходит (✅ по всем пунктам).

## Тебе проверить
1. Большие числа отображаются корректно в окне денег в отладке (выдай себе 1e40).
2. Игра выглядит как раньше (мир, Индекс, шкала).

**Готово, когда:** число биомов берётся из `ZoneData.count()`, `NumFmt` решён, инструменты `check_biome.py` и `new_biome.py` работают.
