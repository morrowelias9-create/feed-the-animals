# Общие правила для задач плана релиза

Каждый файл задачи начинается словами «Прочитай `docs/tasks/release/_RULES.md`». Здесь то, что действует всегда. Эти правила **дополняют** `CLAUDE.md` и не отменяют его. Если что-то здесь противоречит `CLAUDE.md`, остановись и скажи об этом владельцу.

## Среда
- Windows, PowerShell. Папка проекта и путь к Godot записаны в `CLAUDE.local.md` (после T54) или в `CLAUDE.md` (до T54).
- В файлах задач команды написаны в стиле bash ради краткости. Эквиваленты PowerShell: `grep -rn "слово" папка` = `Select-String -Path "папка\*" -Pattern "слово" -Recurse` (или встроенный поиск агента по этой папке); `ls` = `Get-ChildItem`; `rm файл` = `Remove-Item файл`; `cat` = `Get-Content`. Папку `/tmp` не используй: временные файлы клади в `.tmp\` в корне проекта (она в `.gitignore` после T54).
- `godot` в командах задач означает путь из переменной `GODOT_BIN` (так же ищет Godot `tools/test.py`) или полный путь из `CLAUDE.local.md`/`CLAUDE.md`. В PowerShell: `& $env:GODOT_BIN --headless --path . ...`.
- Запуск скриптов Godot без окна: `godot --headless --path . -s путь/к/скрипту.gd`. В режиме `-s` автозагрузок (`Game`, `Loc`, `Save`) нет, как в `tests/run_tests.gd`; бери их из дерева, как делают тесты. Если пишет «класс не найден», один раз выполни `godot --headless --path . --import`.

## Как работать
1. Делай **только** то, что написано в файле задачи. Ничего «заодно» не улучшай.
2. Шаги выполняй **по порядку**.
3. `СТОП: спроси владельца` означает: остановись, задай вопрос дословно как написано и жди ответа. Не выбирай сам, даже если вариант «по умолчанию» кажется очевидным.
4. Если шаг не получается или результат не совпадает с описанием — **остановись и опиши проблему**. Не обходи её, не отключай тесты, не меняй ожидаемые значения в тестах ради зелёного результата.
5. **Поиск по коду.** `CLAUDE.md` запрещает глобальную инвентаризацию проекта. Эти задачи разрешают одно исключение: команда `grep` по `scripts/`, `autoload/`, `tools/`, `tests/`, `docs/`, `web/` с конкретным словом, как написано в шаге. Нельзя читать все файлы подряд и искать по всему проекту «на всякий случай». Не угадывай имена: нашёл — работай, не нашёл — напиши об этом в отчёте.
6. Коммит и push — только по слову владельца «фиксируй» и только по правилам раздела «Главные правила» в `CLAUDE.md`. **До окончания T54 ничего не коммить и не пушь**, потому что там два противоречащих правила.
7. Код: комментарии на русском, имена на английском, видимый игроку текст только через `Loc.t("ключ")` на ru и en (и tr, если язык оставлен после T60). Исключение: текст отладочной панели из T56a может быть без `Loc` (панель есть только в отладочной сборке).
8. Данные уже выпущенных биомов не менять, если задача прямо не требует.

`CLAUDE.md` запрещает менять каркас и файлы спецификаций без разрешения. Эти задачи его дают, только перечисленное:

| T56 | `tools/check.py`, `tools/check_loc.py`, код и тесты ради падений |
| T56a | `scripts/debug/`, `scenes/main.gd` (подключение панели), `CLAUDE.md` (строка про отладку) |
| T57 | `docs/reference/R1_WORLD.md`, `R3_BALANCE.md`, `R4_DATA.md`, `docs/tasks/world/T46.md`, `tools/sim_*.py`, новые `tools/dump_data.*` |

Любая правка вне таблицы — остановись и спроси.

## Проверки (когда задача говорит «запусти проверки»)
```
python tools/check.py
python tools/check_loc.py
python tools/check_assets.py
python tools/test.py
godot --headless --path . --editor --quit
```
Читай весь вывод: ошибки скриптов могут печататься при нулевом коде возврата. Если проверка упала **не из-за твоих изменений**, не чини её (это T56): запиши в отчёт раздел «Уже было красным». Новые тесты добавляй как функции `_test_...` в `tests/run_tests.gd` по образцу соседних (например `_test_luck_pity`) и вызывай их из общего списка там же.

## Журнал и коммиты (по `CLAUDE.md`)
- В `docs/PROGRESS.md` у каждой задачи есть строки `- [ ] **Txx** название`, `  - коммит: ...`, `  - зафиксировано: нет/да`. Когда задача сделана и проверена, поставь `[x]` и допиши 1–3 строки в «Журнал» внизу (что сделано, «решение: ...», что не проверено).
- Название коммита берётся **дословно** из строки `коммит:` этой задачи. Таблица названий — в T55.

## Отчёт (формат из `CLAUDE.md`, раздел «Итоговый отчёт»)
1. Что сделано.
2. Изменённые файлы.
3. Что проверено (команда и результат) и что **не** проверено (телефон, веб, реальный Яндекс SDK, живая игра).
4. Что осталось или вызывает сомнения (если ничего, «нет»). Сюда же «Уже было красным».
5. Что пользователю стоит посмотреть самому: скопируй пункт «Тебе проверить» из задачи.
Закончи фразой: «Если всё в порядке, напиши „фиксируй“». Последним действием выполни `powershell -ExecutionPolicy Bypass -File tools\notify.ps1 "Готово: <название задачи>"`.
