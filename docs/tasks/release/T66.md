# T66 — Метрики и безопасная настройка на лету

Прочитай `docs/tasks/release/_RULES.md`, `CLAUDE.md`, `docs/PROGRESS.md`, `docs/tasks/T24c.md`, `docs/reference/R5_SAVE.md`, `docs/reference/R7_YANDEX.md`.

**Зачем.** После релиза менять числа можно **только флагами**. Нужно (1) измерять, как игроки проходят биомы, и (2) иметь флаги для самых важных множителей. Все значения флагов обязаны обрезаться безопасным диапазоном: ошибка в консоли не должна ломать игру.

## Часть 1. Метрики в сохранении

### Поля (добавь в `Save.DEFAULTS`, ничего не удаляй и не переименовывай)
- `metrics_zone_enter_s`: массив длиной `ZoneData.count()`; значение — активное время игры (секунды) на момент первого входа в биом, `-1` если не заходил.
- `metrics_active_s`: общее активное время игры (секунды).
- `metrics_purchases`: массив записей `{"id": "<id покупки>", "t": <активные секунды>}`. Максимум 200 записей: при переполнении удаляй самые старые.

### Что такое «активное время»
Секунды, пока игра запущена, окно в фокусе и игрок не в окне оффлайн-дохода. Считай в `_process` автозагрузки `Game`: добавляй `delta`. Не считай при паузе и при уходе в фон.

### Миграция
Если поле `metrics_zone_enter_s` короче, чем `ZoneData.count()` (старое сохранение или новый биом) — дополни `-1`. Сохранение без этих полей грузится без ошибок и без потерь других данных. Следуй `R5_SAVE.md`.

### Запись
- Первый вход в биом: найди в коде место, где игра определяет «игрок вошёл в биом N» (grep `zone_entered`/`current_zone`). Запиши `metrics_active_s`, если для этого биома там `-1`.
- Покупка еды, турника, слота, расширения участка: запиши `{id, t}`.
- **Ничего не отправляй в сеть.** Только в локальное сохранение.

## Часть 2. Флаги
Используй существующий механизм флагов (T24c): `Game._load_remote_config()`, поля `remote_*`, `Ya.get_flags(defaults)`. Уже есть: `ad_interval_s`, `ad_first_s`, `boost_s`, `zones_open` (T62). Добавь:
| Флаг | Значение по умолчанию | Допустимый диапазон | Что делает |
|---|---|---|---|
| `offline_rate` | 0.10 | 0.0 – 0.5 | доля дохода за оффлайн |
| `xp_mult` | 1.0 | 0.5 – 2.0 | множитель опыта турников |
Проверь также `boost_s`: если у него нет обрезки диапазона, добавь (по умолчанию как сейчас, диапазон от 0,5× до 2× исходного значения).
Правила для каждого флага: значение берётся с сервера; если оно не число, пустое, NaN или вне диапазона — **обрезается к диапазону**; если не число совсем — берётся значение по умолчанию. Флаг, отсутствующий на сервере, равен значению по умолчанию.
Применение: `Economy.offline_gain` берёт ставку из `Game.remote_offline_rate` (по умолчанию `GameConfig.OFFLINE_RATE`), а не из константы напрямую. Опыт турников умножается на `xp_mult`.

## Тест (headless)
- Метрики (в `tests/run_tests.gd`): имитируй вход в биомы и покупки; массивы заполняются, на 201-й покупке длина остаётся 200.
- Миграция: загрузи старое сохранение без полей (создай его в тесте) — игра не падает, поля добавлены.
- Флаги: значения `"abc"`, `-5`, `99`, `0.3` для `offline_rate` дают соответственно 0.10, 0.0, 0.5, 0.3.

## Проверка
Все проверки из `_RULES.md` + новый тест. `python tools/check.py` не жалуется на новые поля.

## Тебе проверить
1. Поиграй 2–3 минуты, купи что-нибудь, посмотри в отладочном окне сохранения (или в сохранённом JSON): `metrics_active_s` растёт, в покупках появилась запись.
2. В отладке подставь флаг `offline_rate = 0.5`: оффлайн-доход в 5 раз больше, чем при 0,1.

**Готово, когда:** изменение флага меняет число в игре без новой сборки; мусорное значение игнорируется; метрики пишутся и переживают перезапуск.
