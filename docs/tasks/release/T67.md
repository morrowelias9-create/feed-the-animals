# T67 — Производительность (бывший T28)

Прочитай `docs/tasks/release/_RULES.md`, `CLAUDE.md`, `docs/PROGRESS.md`, `docs/tasks/T28.md`, `docs/reference/R2_GAMEPLAY.md`. Требуется T56a.

**Зачем.** Игра идёт на телефонах в браузере. Бюджет: **не больше 100 `MeshInstance3D` в кадре** и **не меньше 30 кадров/с** на целевом телефоне. По цифрам из журнала бюджет, скорее всего, превышен (мир 58, питомцы 11, турник до 22, аватар 6, загон до 60, соседи), но никто не мерил.

## Часть 1. Инструменты измерения

### 1.1 Отладочная плашка
В `scripts/debug/` есть только `zoo.gd` (зоопарк зверей), панель — `debug_panel.gd` из T56a. Добавь плашку с FPS в панель (только отладка, включается кнопкой «Показать FPS и меши»):
- FPS: `Engine.get_frames_per_second()`;
- мешей в кадре: `RenderingServer.get_rendering_info(RenderingServer.RENDERING_INFO_TOTAL_OBJECTS_IN_FRAME)`;
- вызовов отрисовки: `RenderingServer.get_rendering_info(RenderingServer.RENDERING_INFO_TOTAL_DRAW_CALLS_IN_FRAME)`.
Если одно из имён констант не существует в Godot 4.7.2 — найди ближайшее в документации редактора и запиши в отчёт, что взял.

### 1.2 Счётчик мешей по сценам (headless)
Создай `tools/count_meshes.gd` (запуск `godot --headless --path . -s tools/count_meshes.gd`). Он строит мир и считает узлы `MeshInstance3D` с `visible = true` в сценариях:
1. старт: игрок один, загон пуст;
2. загон на 20 зверей;
3. загон на максимум зверей (60 мешей по журналу);
4. сосед: 4 загона по снимкам;
5. все питомцы выданы;
6. Океан (последний биом) на среднем месте;
7. турник максимального вида.
Выводит таблицу «сценарий → меши». Если построить сценарий через реальные функции нельзя — опиши в отчёте, что именно не получилось.

## Часть 2. Измерение
1. Запусти счётчик. Запиши таблицу в отчёт.
2. **СТОП: спроси владельца** (замер на телефоне). Дай инструкцию: «Открой отладочную сборку в браузере на телефоне, включи плашку, посмотри FPS и число мешей в 4 местах: загон на 20 зверей, у соседа, у питомцев, в Океане. Пришли цифры». Назови целевой телефон: уточни у владельца модель.

## Часть 3. Оптимизация (только если мешей > 100 или FPS < 30)
Применяй по одному приёму, после каждого измеряй заново. Порядок:
1. **Режим А (1 меш на зверя)** для соседей и для зверей далеко от игрока. По журналу T24f у зверя 3 режима отрисовки; переключатель — `GameConfig.PEN_PARTS_ENABLED` и `AnimalView` (`grep -rn "PEN_PARTS_ENABLED\|part_mode" scripts autoload`). Включи самый лёгкий режим для зверей соседей и для зверей загона, когда их больше 20.
2. **Ленивый декор:** декор биома строится только для зоны рядом с игроком и соседних. Остальные зоны — без декора, строятся при приближении, удаляются при удалении (с задержкой, чтобы не мигали).
3. **`visibility_range_end`** для декора и дальних зверей (подбери по виду: объект не должен «выскакивать» заметно).
4. Слияние статичных мешей одной зоны (`MultiMeshInstance3D` или объединение), если приёмов 1–3 не хватило.
Не снижай качество главных объектов в центре внимания (зверь в руках, зверь при получении).

## Проверка
- Таблица «до/после» в отчёте.
- Все проверки из `_RULES.md`.

## Тебе проверить
1. На телефоне: во всех четырёх местах ≥ 30 FPS, меши ≤ 100.
2. Ничего не «выскакивает» и не пропадает на глазах при ходьбе вдоль коридора.

**Готово, когда:** цифры записаны в `docs/reference/R3_BALANCE.md`→ раздел «Производительность», на целевом телефоне ≥ 30 кадров/с, бюджет мешей соблюдён.
