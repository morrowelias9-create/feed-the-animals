# T58 — «Счастливый бросок» и «Подробности»

Прочитай `docs/tasks/_RULES.md`, `CLAUDE.md`, `PROGRESS.md`, `docs/tasks/T24a.md`, `docs/reference/R3_BALANCE.md`, `docs/reference/R9_MONETIZATION.md`.

**Зачем.** Игрок может купить «Счастливые броски» (`lucky_5`, `lucky_25`), но в игре ничего не происходит. Это нарушение магазина Яндекса: платный товар обязан работать. Заодно делаем кнопку «Подробности» честной: она показывает те шансы, по которым игра реально бросает.

## Что значит «счастливый бросок» (решение уже принято)
- `lucky_5` даёт 5 счастливых бросков, `lucky_25` — 25. Они **складываются** с уже имеющимися.
- В счастливом броске **шансы всех мутаций умножаются на 2** (число хранится одной константой `LUCKY_MUT_MULT := 2.0`, чтобы владелец мог поменять).
- Итоговый шанс мутации не может быть больше `0.5` (константа `LUCKY_MUT_CAP := 0.5`).
- Счастливый бросок тратится при каждом броске, который закончился находкой зверя (то есть при каждом обычном броске). Промах, отмена, повторный клик — не тратят.
- Счётчик остатка хранится в сохранении и переживает перезапуск.

## Шаги

### 1. Найди, что уже есть
Выполни и запиши выводы в отчёт:
- `grep -rn "lucky" scripts tools docs`
- `grep -rn "Подробности\|details" scripts --include=*.gd`
- `grep -rn "mutation_chance\|MUTATION" scripts --include=*.gd`
В `ShopData` найди товары `lucky_5` и `lucky_25`, в `Save.DEFAULTS` — поле счётчика счастливых бросков (оно уже может быть, например `lucky_throws`). Если поля нет — добавь `lucky_throws: 0` в `Save.DEFAULTS` (без удаления и переименования других полей).

### 2. Начисление при покупке
Найди обработчик успешной покупки (`consume` в слое инап-покупок, см. T24a). Для `lucky_5` добавь `lucky_throws += 5`, для `lucky_25` — `+= 25`, затем сохрани игру. Проверь, что покупка не начисляет дважды при повторном вызове (идемпотентность по токену покупки, как у остальных товаров).

### 3. Константы
В `RollData` (или рядом с остальными числами мутаций — найди сам шаг 1) добавь `LUCKY_MUT_MULT := 2.0` и `LUCKY_MUT_CAP := 0.5`.

### 4. Применение в броске
В `SpawnRoller` (найди grep-ом) в функции, считающей шансы мутаций, добавь параметр `lucky: bool`. Если `lucky` — каждый шанс мутации умножь на `LUCKY_MUT_MULT` и ограничь `LUCKY_MUT_CAP`. Никаких копий таблиц шансов: используй те же функции и таблицы, что и для обычного броска.
В месте, где игра запускает бросок, передай `lucky = (Game.lucky_throws > 0)`. После успешной находки уменьши счётчик на 1 и сохрани.

### 5. Показ в HUD
Если рядом с кнопкой броска есть место, покажи «Счастливых: N» (ключ `Loc` на ru/en), только когда `N > 0`. Если места нет — не показывай, только запиши в отчёт.

### 6. «Подробности»
Кнопка показывает шансы **текущего** броска. Данные берутся из тех же функций `SpawnRoller` (шансы зверей по рангам, шансы мутаций, шансы размеров) с учётом удачи, текущей еды и `lucky`. Нельзя вставлять числа руками или копировать таблицы. Если для окна нужны шансы в виде списка — добавь в `SpawnRoller` функцию `get_odds(ctx)`, которую используют и бросок, и окно.

### 7. Тест-стенд на 10 000 бросков
Создай headless-тест (положи рядом с другими тестами; как они запускаются — в `tools/test.py`). Тест:
1. Берёт фиксированный контекст (зона 2, еда этой зоны, `lucky = false`), делает 10 000 бросков через `SpawnRoller`, считает долю каждой мутации.
2. То же с `lucky = true`.
3. Сравнивает доли с `get_odds()` с допуском 1,5 процентного пункта (абсолютно).
4. Проверяет: в `lucky = true` доля каждой мутации примерно в 2 раза выше (или упёрлась в потолок 0,5).
5. Проверяет тест на покупку: `lucky_5` → счётчик +5; бросок → −1.
Запусти генератор случайных чисел с фиксированным семенем, чтобы тест был стабильным.

## Проверка
Запусти все проверки из `_RULES.md`, плюс новый тест.

## Тебе проверить
1. В режиме отладки выдай себе `lucky_5`. Сделай 5 бросков: счётчик уменьшается 5→0. На шестом броске счастливого значка нет.
2. Закрой и открой игру посреди серии: остаток сохранился.
3. Открой «Подробности» до и после выдачи `lucky_5`: шансы мутаций в счастливом режиме примерно в 2 раза выше.

**Готово, когда:** покупка `lucky_5` даёт 5 бросков с повышенными шансами, «Подробности» совпадает с результатами стенда на 10 000 бросков.
