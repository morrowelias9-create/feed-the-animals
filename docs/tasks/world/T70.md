# T70 — SDK в черновике Яндекса

Прочитай `docs/tasks/_RULES.md`, `CLAUDE.md`, `PROGRESS.md`, `docs/reference/R7_YANDEX.md`, `docs/reference/R9_MONETIZATION.md`, `docs/tasks/T22.md`, `T23.md`, `T24.md`, `T24a.md`, `T24b.md`, `T24c.md`.

**Зачем.** До релиза нужно убедиться, что всё, что игра просит у Яндекса, существует в консоли с теми же названиями. Агент не видит консоль, поэтому: агент составляет точный список «что есть в коде», владелец сверяет с консолью.

## Шаги

### 1. Составь список имён из кода
Создай `docs/checks/YANDEX_NAMES.md` с таблицей. Для каждой строки укажи **файл и строку** в коде.
- **Реклама:** вызовы межстраничной (interstitial) и вознаграждаемой (rewarded) рекламы. Найди: `grep -rn "showFullscreenAdv\|showRewardedVideo\|interstitial\|rewarded" scripts web`.
- **Инап-покупки:** все `id` товаров из `ShopData` (должно быть **9**). Для каждого: id, название, цена в яанах, что даёт, как выдаётся (`consume` или постоянный).
- **Лидерборд:** имя `best_throw` (проверь написание везде одинаково).
- **Облачные сохранения:** какие данные и как называются (`getPlayer`, `setData`, `getData`).
- **Флаги:** `ad_interval_s`, `ad_first_s`, `boost_s`, `zones_open`, `offline_rate`, `xp_mult` (последние два из T66): имя, значение по умолчанию, диапазон.
- **Сессии для соседей:** названия данных, которые игра пишет/читает для асинхронного мультиплеера.
Если имена в коде в разных местах написаны по-разному (например `bestThrow` и `best_throw`) — выпиши расхождения в отчёт и **СТОП: спроси владельца**, какое имя в консоли.

### 2. СТОП: владелец сверяет с консолью
Дай владельцу таблицу и скажи: «Открой консоль → игра → черновик. Для каждой строки поставь ✅, если в консоли есть точно такое имя (товар, лидерборд, флаг). Что отсутствует — создай в консоли или пришли мне список расхождений».
Для создания в консоли пиши подсказки: тип флага — строка/число; лидерборд — по убыванию, тип числа; инап-товар — потребляемый или нет по таблице.

### 3. Исправь код по расхождениям
Для каждой строки «нет в консоли» владелец выбирает: создать в консоли или переименовать в коде. Если переименование — поправь код и таблицу, затем `grep -rn "старое_имя" .` чтобы не осталось следов.

### 4. Сборка в черновик
Запусти `python tools/build.py`. Скажи владельцу, какой файл загрузить в черновик.

### 5. Ручная проверка в черновике (владелец)
Дай список для проверки в браузере на странице черновика:
1. Межстраничная реклама показывается через `ad_first_s` секунд после начала, затем раз в `ad_interval_s`. Закрытие рекламы продолжает игру.
2. Кнопка буста x2: показывается вознаграждаемая реклама, после просмотра буст включился на `boost_s` секунд. Если закрыть рекламу раньше — буст **не** выдан.
3. Покупка каждого из 9 товаров (в тестовом режиме Яндекса): товар выдан один раз, после перезапуска игры остаётся (для постоянных) или тратится (для потребляемых).
4. Лидерборд: после рекордного броска запись появилась.
5. Облачные сохранения: закрой игру, очисти локальные данные браузера, открой снова — прогресс на месте (войди в аккаунт Яндекса, если игра просит).
6. Соседи: на двух аккаунтах зайти по очереди, увидеть друг друга по снимкам (T24b).
7. Флаги: поменяй `boost_s` в консоли, перезапусти: значение подхватилось.

## Проверка
Все проверки из `_RULES.md`.

## Тебе проверить
Пункты 1–7 из шага 5, результаты запиши в `docs/checks/YANDEX_NAMES.md` (✅/❌ и заметка).

**Готово, когда:** все названия из кода совпадают с консолью, пункты 1–7 пройдены.
