# T48. Горизонтальная шкала броска с сегментами биомов

**Зависит от:** T44 (T45 желательно).  
**Читать:** `R2_GAMEPLAY.md` (бросок), `R6_UI.md` (HUD, шкала). Файлы: `scripts/ui/throw_meter.gd` (переписывается), `scripts/world/throw_controller.gd` (`action_pressed`, `_enter_aiming`, `_cancel_aiming`), `scripts/logic/throw_scale.gd` (T44), `scripts/data/mini_zone_data.gd` (T44), `scripts/ui/stat_icon.gd` (образец иконки с PNG-подменой), `scripts/ui/ui_style.gd`, `scripts/ui/hud.gd` (где создаётся и размещается шкала; `grep -n "ThrowMeter" -r scripts tests`).

## Цель

Заменить вертикальную шкалу, которая лишь добавляет бонус 0…20 к силе, на горизонтальную шкалу выбора дальности с сегментами по биомам. Игрок останавливает ползунок в сегменте нужного биома, и еда падает в этот биом. Правый, самый широкий сегмент это «максимальная дальность».

## Поведение

- Число сегментов `n = ThrowScale.open_zones(dmax)`, где `dmax = ThrowScale.max_distance(Game.strength())`.
- Ширины сегментов `ThrowScale.segment_widths(n)`: например при трёх открытых биомах 25 % / 25 % / 50 %.
- Дальность броска `ThrowScale.distance_at(v, n, dmax)`, где v это положение ползунка 0…1. Бросок в сегмент старого биома гарантированно падает в этот биом, в последний сегмент даёт дальность от начала последнего биома до максимума.
- «Идеально!» это `ThrowScale.is_perfect(v)` (правые 5 % шкалы).
- Ползунок идёт слева направо и обратно (треугольная волна, как сейчас по вертикали), период туда-обратно `ANIM_PERIOD = 2.6` секунды (раньше 1,4).

## Что сделать

### 1. `scripts/ui/throw_meter.gd` (переписать)

Класс остаётся `ThrowMeter`, `extends Control`, полноэкранный, `mouse_filter = IGNORE`. Публичный интерфейс:

```gdscript
func configure(open_zones: int, dmax: float) -> void   # задать сегменты и максимум; вызывается перед start()
func start() -> void
func stop() -> float          # остановить, вернуть v (0…1)
func get_value() -> float
func distance_for(v: float) -> float   # ThrowScale.distance_at(v, _open, _dmax)
func current_distance() -> float       # distance_for(_v)
```

`configure` не зависит от дерева сцены (его вызовут и тесты): только сохраняет числа, считает массивы границ, вызывает `queue_redraw()`.

Размещение (координаты в пикселях базового вида 1280×720, но брать ширину из `size.x`, чтобы на широких экранах шкала была по центру):

- Ширина шкалы `bar_w = minf(1200.0, size.x − 80.0)`, левый край `x0 = (size.x − bar_w) / 2`.
- Капсула: `Rect2(x0, 470, bar_w, 60)`. Чёрная внешняя подложка со скруглением 30, внутри на отступе 4 пикселя цветные сегменты.
- Цвет сегмента биома i: `Color.html(ZoneData.ZONES[i]["ground"])`. Между сегментами чёрные разделители толщиной 5. Скругление только внешних углов первого и последнего сегмента (в `StyleBoxFlat` задать `corner_radius_*` отдельно для левых или правых углов).
- Над каждым сегментом круглая иконка биома диаметром 44, центр по середине сегмента, `y = 440`: чёрное кольцо толщиной 3, заливка цветом сегмента, внутри первая буква названия зоны (`Loc.t(ZoneData.ZONES[i]["name_key"])`), шрифт `UiStyle.font()` размером 26, белым с чёрной обводкой (`draw_string_outline`, затем `draw_string`). Если существует файл `res://assets/ui/icons/zone_<id>.png`, рисовать его вместо буквы (проверка `ResourceLoader.exists`, как в `StatIcon`).
- Иконка сегмента, в котором сейчас ползунок, увеличена в 1,25 раза.
- Ползунок: белый скруглённый прямоугольник 14×84, центр по высоте капсулы (`y = 500`), по X в `x0 + v * bar_w`; под ним полупрозрачная подложка 26×96 (цвет `Color(1,1,1,0.25)`).
- Подпись над ползунком (`y = 395`), по центру на ползунке, но в пределах капсулы: `Loc.t(MiniZoneData.name_key(зона, мини)) + "  " + str(int(дальность)) + " " + Loc.t("unit_m")`, где зона и мини-зона берутся из `ZoneData.zone_at(дальность)` и `MiniZoneData.index_at(дальность)`. Подпись это `UiStyle.outline_label(..., 34, 6, UiStyle.COLOR_TEXT)`; текст обновлять только когда он изменился.
- Ключ `unit_m` добавить в `Loc.T` (ru «м», en «m»), если его нет.
- `StyleBoxFlat` для рисования создавать **один раз** в `configure` или `_ready` и хранить в полях, а не создавать в `_draw` каждый кадр. Перерисовка (`queue_redraw`) только пока ползунок движется.
- Убрать старые константы вертикальной шкалы (`X_MIN`, `Y_MIN`, `TICKS_Y`, `SEGMENT_COLORS` и подпись «+N»).

### 2. `scripts/world/throw_controller.gd`

- В `_enter_aiming()` перед `_meter.start()` вызвать `var dmax: float = ThrowScale.max_distance(Game.strength())` и `_meter.configure(ThrowScale.open_zones(dmax), dmax)`.
- В `action_pressed()` вместо расчёта через `ThrowCalc.eff_power`: `var v: float = _meter.stop()`, `var dist: float = _meter.distance_for(v)`, `_perfect = ThrowScale.is_perfect(v)`. Остальной код (`_zone = ZoneData.zone_at(dist)`, `_dist = dist`, траектория, анимация) не менять.
- Функции `ThrowCalc.bonus_of`, `eff_power`, `distance`, `is_perfect` оставить (на них есть тесты), но из броска они больше не вызываются.

## Ограничения

- Не менять формулы дохода, распределения зверей, траекторию полёта и камеру броска.
- Не создавать узлы и объекты в `_process`.
- Кнопки и области касания не нужны: бросок по тапу в любом месте, как сейчас.
- Файлы `docs/reference/` не править (в `R6_UI.md` описана старая шкала: сообщить пользователю).

## Проверка

`python tools/check.py`, `python tools/test.py`, `python tools/check_loc.py`, Godot headless; запуск игры с окном: проверить шкалу при 1, 2, 3 и 5 открытых биомах (менять `Save.data["strength"]` для проверки, например 5, 40, 120, 400, 500).

## Критерии готовности

- Шкала горизонтальная, число сегментов равно числу открытых биомов, иконки над сегментами.
- Остановка ползунка в сегменте старого биома даёт бросок в этот биом (проверить по полю `_zone` или по подписи).
- Ползунок медленнее прежнего, на узких сегментах игра остаётся играбельной.
- Шкала не закрывает подсказку «Нажмите, чтобы бросить!» и панель еды.

**Тебе проверить:** на телефоне и на компьютере бросить в каждый сегмент при 3 и 5 открытых биомах; оценить, насколько легко попасть в самый узкий сегмент (если трудно, написать, на каком количестве сегментов, и мы подберём скорость или «липкие» границы).
