# T54 — Уборка репозитория и правил агента

Прочитай `docs/tasks/_RULES.md`, `CLAUDE.md`, `PROGRESS.md`.

**Зачем.** Репозиторий стал публичным. В корне лежит мусор, в `CLAUDE.md` два противоречащих раздела, а в `tools/` лежит секретная тема уведомлений. Это нужно убрать до релиза.

**Трогаем только:** корень репозитория, `.gitignore`, `CLAUDE.md`, `tools/ntfy_topic.txt` и места, где он читается. Код игры не трогаем.

## Шаги

### 1. Составь список на удаление (ничего пока не удаляй)
Выполни `git status --short` и `ls -la` в корне. Найди, что из списка существует:
- `test_*.txt` в корне (должно быть 11 файлов);
- `game_error.txt`, `game_output.txt`, `output.log`, `python_env.txt`;
- `T24f.patch`, `old_tests.gd`, `old_scenery.gd` и их `.uid`;
- `label_far.png.import`, `label_near.png.import`;
- `.uid` файлы с именами `test_minimal`, `test_world`, `test_scenery_access`.

Для каждого файла проверь, что на него никто не ссылается: `grep -rn "имя_файла" scripts tools docs project.godot`. Если ссылка есть — пометь файл «используется» и **не** включай в удаление.

### 2. СТОП: спроси владельца
Покажи список «будет удалено» и список «используется, оставляю». Спроси: «Удалить эти файлы? (да / нет / убрать из списка: ...)». Жди ответа.

### 3. Удали подтверждённое
Для отслеживаемых файлов: `git rm <файл>`. Для неотслеживаемых: `rm <файл>`. Не удаляй ничего, чего не было в подтверждённом списке.

### 4. `.gitignore`
Добавь строки (только те, которых ещё нет):
```
*.log
test_*.txt
game_output.txt
game_error.txt
python_env.txt
*.patch
CLAUDE.local.md
tools/ntfy_topic.local.txt
```

### 5. `CLAUDE.md`: один раздел «Главные правила»
1. Найди оба раздела «Главные правила». Выпиши в отчёт, чем они противоречат друг другу (про `git push`).
2. Оставь **один** раздел. Правило про push в нём: «Не коммить и не пушить, пока владелец не написал «фиксируй». После «фиксируй» — коммит и push».
3. Остальные пункты из обоих разделов объедини без повторов. Если два пункта противоречат друг другу, кроме push, — `СТОП: спроси владельца` и покажи оба пункта.
4. Найди локальные пути и имя пользователя Windows: `grep -nE "C:\\\\|C:/|Users" CLAUDE.md`. Вырежи эти строки из `CLAUDE.md` и положи в новый файл `CLAUDE.local.md` в корне (он в `.gitignore`).
5. В `CLAUDE.md` добавь одну строку: «Локальные пути (Godot, проект) лежат в `CLAUDE.local.md`, он не в репозитории. Если файла нет — спроси владельца».

### 6. Тема уведомлений `tools/ntfy_topic.txt`
1. Найди, кто читает файл: `grep -rn "ntfy_topic" . --include=*.py --include=*.md --include=*.sh --include=*.bat --include=*.gd`.
2. Создай новую случайную тему командой `python -c "import secrets; print('fta-' + secrets.token_urlsafe(12))"`.
3. Запиши её в `tools/ntfy_topic.local.txt` (он в `.gitignore`).
4. Поправь всё, что читало `tools/ntfy_topic.txt`, чтобы оно читало `tools/ntfy_topic.local.txt`. Если файла нет — скрипт молча пропускает отправку уведомления.
5. `git rm tools/ntfy_topic.txt`.
6. В отчёте напиши: «Старая тема осталась в истории git. Подпишись на новую тему в приложении ntfy, старую считай публичной. Историю не переписывали».

### 7. Поиск ключей
Выполни: `grep -niE "key|token|secret|password|api_key" export_presets.cfg web/shell.html`. Выпиши найденные строки в отчёт. **Ничего не меняй**, если строка похожа на настоящий ключ — `СТОП: спроси владельца`. Если находятся только слова вроде `keyboard`, `key_name` в обычном коде — пиши «ключей нет».

## Проверка
- `git status --short` в корне не показывает мусора.
- `grep -c "Главные правила" CLAUDE.md` выводит `1`.
- `grep -rn "ntfy_topic.txt" .` ничего не находит, кроме `.gitignore`/истории.
- `godot --headless --editor --quit` без новых ошибок.

## Тебе проверить
1. Открой `CLAUDE.md`: один раздел «Главные правила», нет путей `C:\...`.
2. Открой `CLAUDE.local.md`: там твои пути.
3. Подпишись в приложении ntfy на новую тему из `tools/ntfy_topic.local.txt`.

**Готово, когда:** корень без мусора, правила не противоречат друг другу, секретной темы в репозитории нет.
