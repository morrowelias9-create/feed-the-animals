# T46. Мини-зоны в мире: оттенок, арки, названия, прогресс, награда

**Зависит от:** T44, T45.  
**Читать:** `R1_WORLD.md` (коридор, арки), `R6_UI.md` (HUD). Файлы: `scripts/data/mini_zone_data.gd` (T44), `scripts/world/world_builder.gd` (`_build_corridor`, `_build_arches`, `_refresh_labels`, `_plane`, `_tex_mat`, `_multimesh`), `scripts/world/world_layout.gd` (`arch_z`, `ARCH_*`), `scripts/ui/hud.gd`, `autoload/game.gd` (`_apply_xp`, `income_per_sec`, сигналы), `autoload/save.gd` (`DEFAULTS`), `docs/budget.json`.

## Цель

Каждый биом визуально делится на 6 мини-зон, и игрок видит прогресс: полосы разного оттенка на полу, низкие арки с названиями, полоса прогресса в HUD, награда при первом достижении новой мини-зоны. Звери и экономика от мини-зон не зависят (кроме небольшой награды).

## Что сделать

### 1. Оттенок пола по мини-зонам

Сейчас пол каждой зоны это одна плоскость (`_build_corridor`, `Corridor0…4`). Нужно, чтобы в каждой зоне 6 полос с разной яркостью `MiniZoneData.SHADE[j]`, при этом число `MeshInstance3D` в мире не должно вырасти больше чем на 5.

Способ (единственный разрешённый): для каждой зоны вместо одной `_plane` строить **один** `ArrayMesh` из 6 прямоугольников (по одному на мини-зону), у вершин каждого прямоугольника задан цвет `Color(s, s, s, 1.0)`, где `s = MiniZoneData.SHADE[j]`. Материал зоны (`_tex_mat("ground_" + id, tint)`) должен использовать цвет вершин как множитель: `vertex_color_use_as_albedo = true`. Перед этим прочитать `_plane` и `_tex_mat` и сохранить те же UV (масштаб текстуры по длине не должен «ехать»: если `_plane` повторяет текстуру по размеру, у нового меша шаг UV на метр должен быть тем же) и ту же позицию по высоте (`-WorldLayout.DROP_H`). Для Океана (бирюзовая «вода» с рябью, T17) проверить, что материал не ломается; если у него свой шейдерный путь, использовать для него тот же приём, но сообщить в отчёте.

Если `_tex_mat` не позволяет включить цвет вершин, остановиться и описать причину пользователю (не переходить на 30 отдельных `MeshInstance3D`).

### 2. Арки мини-зон

Арки между зонами (`_build_arches`) остаются. Для 5 границ мини-зон внутри каждой зоны (25 штук) сделать **низкие арки-ленты**:

- Все 25 балок собрать в **один** `MultiMeshInstance3D` (посмотреть, как это сделано в мире через `_multimesh`). Размер балки: ширина как у большой арки (`2 * CORRIDOR_HALF_W`), высота `0.6`, толщина `0.4`, высота подвеса `ARCH_BEAM_Y`. Цвет: цвет `ground` зоны, осветлённый на 20 % (`Color.lightened(0.2)`).
- Для каждой арки одна `Label3D` с названием следующей мини-зоны: `Loc.t(MiniZoneData.name_key(zone, j))`; шрифт через `UiStyle.apply_font_3d`, `font_size = 96`, `pixel_size = 0.012`, обводка как у больших арок. Метки обновляются при смене языка (`Loc.language_changed`), как `_refresh_labels`.
- Позиция арки: `z = -MiniZoneData.start_m(zone, j)` для j = 1…5.
- Для первой мини-зоны (j = 0) арки нет: начало зоны отмечено большой аркой.

### 3. Прогресс и награда

Награда за вход в новую мини-зону выдаётся **когда еда залетела в мини-зону** (функция `Game.report_flight_distance`), а не при росте силы. Для старых сохранений миграция делается через `Game.init_mini_zone()`: индекс берётся из рекордного броска без награды.

1. `autoload/save.gd` в `DEFAULTS` добавить `"mini_reached": -1,  # T46: максимальный глобальный номер мини-зоны, достигнутый дальностью полёта еды (-1: не инициализировано)`.
2. В `autoload/game.gd` добавить сигнал `mini_zone_reached(zone: int, index: int, reward: float)` и метод `init_mini_zone()` для миграции старых сохранений:
   - если `Save.data["mini_reached"] < 0`, считает `g = MiniZoneData.global_index(Save.data["best_throw"])` (если есть), иначе 0; записывает `mini_reached = g` **без награды** и сохраняет.
3. Метод `report_flight_distance(dist: float)` вызывается `RevealController` после приземления еды:
   - считает `g = MiniZoneData.global_index(dist)`;
   - если `g > mini_reached`, начисляет **одну** награду за все новые мини-зоны сразу: `reward = maxf(income_per_sec() * MiniZoneData.ENTRY_REWARD_S, ENTRY_REWARD_MIN_K * base_зоны)`, где `base_зоны` это `ZoneData.ZONES[зона_достигнутой]["base"]`, `ENTRY_REWARD_S = 120.0`, `ENTRY_REWARD_MIN_K = 20.0` (константы в `MiniZoneData`), прибавляет к деньгам, записывает `mini_reached = g`, вызывает `Save.save_data()`, испускает `mini_zone_reached` с зоной и индексом достигнутой мини-зоны.
4. При старте игры после загрузки сохранения вызывать `init_mini_zone()` (миграция старых сохранений).
3. В `scripts/ui/hud.gd` показать плашку при `mini_zone_reached`: текст «Новая местность: <название>», строка ниже «+<сумма>» через `NumFmt`. Показ 3 секунды с плавным появлением и исчезновением (как другие уведомления `Game.notice`; если подходит, использовать существующий механизм `notice` с ключом и аргументами и добавить ключ `mini_zone_new` в `Loc.T`: ru «Новая местность: {0}», en «New area: {0}»; сверить, как подставляются аргументы в `notice`). Плашка не должна накладываться на подсказку и цель HUD: посмотреть их расположение в `hud.gd` и разместить в свободном месте.
4. В HUD слева вверху добавить `ZoneProgress` (новый скрипт `scripts/ui/zone_progress.gd`, `class_name ZoneProgress`, `extends Control`): название зоны и мини-зоны текущей максимальной дальности («Саванна · Водопой 3/6») и тонкая полоса (высота 14, ширина 320) с долей `MiniZoneData.progress_in(dmax)`. Шрифт через `UiStyle.outline_label` (размер 28). Обновляется по сигналам `Game.strength_changed` и `Loc.language_changed`, не в `_process`. Скрывается в тех же режимах, где HUD скрывает другие плашки (см. `_update_visibility` в `hud.gd`).
5. Новые ключи `Loc.T`: `zone_progress_fmt` (ru «{0} · {1} {2}/6», en «{0} · {1} {2}/6») или собирать строку из частей без формата, если `Loc.t` не поддерживает подстановку. Проверить, как подставляются значения в существующих текстах, и сделать так же.

### 4. Тесты

- Проверка, что `Game.init_mini_zone()` при `mini_reached == -1` не начисляет награду и записывает индекс из `best_throw` (если `Game` недоступен в `run_tests.gd`, вынести расчёт награды в чистую функцию `MiniZoneData.entry_reward(income: float, zone: int) -> float` и проверить её: при нулевом доходе даёт `20 * base`, при большом доходе даёт `income * 120`).
- Проверка, что `Game.report_flight_distance()` начисляет награду при входе в новую мини-зону и не начисляет повторно.
- `MiniZoneData.SHADE.size() == MiniZoneData.PER_ZONE`.

## Ограничения

- Не добавлять `OmniLight3D`, `SpotLight3D`, `ShaderMaterial`, тени. Не создавать объекты в `_process`.
- `MeshInstance3D` в кадре не более 100: записать в «Журнал» итоговое число в мире (как в T45).
- Не менять звери, цены, баланс.

## Проверка

`python tools/check.py`, `python tools/test.py`, `python tools/check_loc.py`, Godot headless; запуск игры с окном, если доступно.

## Критерии готовности

- В каждой зоне видны 6 полос пола разной яркости, между ними низкие арки с названиями.
- В HUD слева вверху название мини-зоны и полоса прогресса; плашка «Новая местность» при росте силы через границу.
- Старое сохранение при первом запуске не получает награду.

**Тебе проверить:** пройти коридор камерой или выбрать максимальную силу в редакторе: полосы пола заметны, но не режут глаза; названия на арках читаются; HUD слева вверху не перекрывает другие элементы на телефонном размере экрана; после повышения силы через границу мини-зоны приходит плашка и деньги.
