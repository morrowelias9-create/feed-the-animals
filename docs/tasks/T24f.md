# T24f. Анимация по частям для зверя в центре внимания

**Назначение:** показать ходьбу и характер зверя крупным планом (экран получения и зверь в руках). Остальные звери остаются с анимацией всего тела из T24d.

**Зависит от:** T24d (принят). Желательно после T24e, но можно сделать на зверях Леса.
**Читать:** `R8_ASSETS.md` (раздел 5.5 и раздел 8), `docs/budget.json`, `CLAUDE.md` (правила 3D).
**Файлы для изучения перед работой (только они):** построитель из T24d, `scripts/data/animal_recipes.gd`, `AnimalView`, `RevealController`, `CarryController`.

## Жёсткие ограничения

1. Не менять игровой цикл, кинематику получения (фазы, длительности, камеру), экономику, сохранения, ввод.
2. Не использовать скелеты, `AnimationPlayer`, `AnimationTree`, `ShaderMaterial`.
3. Не больше 12 `MeshInstance3D` на такого зверя и не больше одного такого зверя в кадре. Звери в загоне остаются в режиме А (один `MeshInstance3D`).
4. Не создавать объекты и меши в `_process`; всё строится один раз при показе зверя.

## Что входит в задачу

1. Построитель получает второй режим: части зверя собираются по `group` из рецепта в отдельные `MeshInstance3D` под общим узлом (тело, голова, 4 лапы, хвост, уши; остальные блоки «other» присоединяются к телу). Материал один на зверя.
2. Анимация частей кодом: лапы качаются по фазе, голова кивает, хвост и уши чуть покачиваются, у зверей без лап (змея, рыба, медуза) движение волной или качкой по частям. Тип по `move` из рецепта.
3. `AnimalView` включает режим Б только для зверя на экране получения и зверя в руках; при возврате в загон снова режим А. Позиции и логика `run_to`/`eat` не меняются.
4. Звери без рецепта (или с внешним `.glb`) остаются как есть: режим Б для них не включается, ошибки нет.

## Тесты

1. Число `MeshInstance3D` в режиме Б не больше 12 для всех зверей с рецептами.
2. Число треугольников в сумме групп равно числу в режиме А (с допуском).
3. Режим А по-прежнему один `MeshInstance3D`.
4. Нет утечек узлов после переключения режимов А → Б → А (число дочерних узлов зверя не растёт).

## Проверки

`python tools/check.py`, `python tools/test.py`, Godot 4.7.2 `--headless --path . --editor --quit` (прочитать весь вывод), игра и зоопарк.

## Тебе проверить

1. Экран получения: ходьба зверя читается, лапы и голова двигаются, сцена не лагает.
2. Зверь в руках выглядит как раньше по размеру и позиции, анимация не мешает.
3. После возврата в загон звери снова в обычном режиме, FPS не упал (проверь на своей машине; на телефоне отдельно).
4. Для змеи, рыбы, медузы движение выглядит правдоподобно.
