# T24d. Рецепты зверей: инфраструктура, Лес, зоопарк

**Назначение:** дать игре собственных блочных зверей без внешних моделей. Звери собираются из блоков по рецептам в данных и запекаются в один меш. Это не новая механика: игровая логика, экономика и сохранения не меняются.

**Зависит от:** T10b, T11b, T13 (выполнены). Не зависит от T25 и T27.
**Читать:** `R8_ASSETS.md` (разделы 1, 2, 5, 8, 9), `R4_DATA.md` (список зверей и размеров), `docs/budget.json`, `CLAUDE.md` (правила 3D).
**Файлы для изучения перед работой (только они):** `ModelLoader`, `AnimalData`, `AnimalView`, `VariantData`, тесты `ModelLoader` в `tests/run_tests.gd`.

## Жёсткие ограничения

1. Не менять игровой цикл, бросок, экономику, сохранения, ввод, размеры зверей (`size_m`), позиции, зоны.
2. Не менять `project.godot`, `export_presets.cfg`, SDK, автозагрузки.
3. Не добавлять плагины, `ShaderMaterial`, `Thread`, новые источники света, `GPUParticles3D`.
4. Сохранить публичные методы `ModelLoader` (в том числе `get_animal(id, variant)`, `height_of`, нормализацию размера и заглушку). Сохранить ключи и семантику вариантов (оттенок, свечение, искры не больше 12, диск у бриллианта).
5. Один зверь это один `MeshInstance3D` и один материал. Не создавать узел на каждый блок.
6. Не создавать меши и текстуры в `_process`; результат кэшируется как прототип и отдаётся копией, как сейчас.
7. Стиль строго по R8, раздел 5 (крепкие фасеточные блоки, фаски, перекосы, матовые вершинные цвета, чек-лист 5.4).

## Что входит в задачу

### 1. Данные рецептов

Новый файл `scripts/data/animal_recipes.gd` (только данные, без узлов). Рецепт зверя: список блоков и тип движения. Формат минимального разумного вида, например:

- блок: `shape` (`box`, `wedge`, `taper`, `sphere`), `group` (`body`, `head`, `leg_fl`, `leg_fr`, `leg_bl`, `leg_br`, `tail`, `ear_l`, `ear_r`, `other`), `pos`, `size`, `rot` (градусы), `color`, `color2` (низ блока для градиента), `taper` (для `taper`), `bevel`;
- `move`: один из `hop`, `waddle`, `trot`, `slither`, `swim`, `idle` (используется в T24d для движения всего тела).

Единицы рецепта относительные: итоговый размер даёт существующая нормализация по `size_m`. Если рецепт даёт другой формат, объяснить в «Журнале» под пометкой «решение».

### 2. Построитель

Новый файл, например `scripts/world/animal_builder.gd`: статические функции без узлов. Принимает рецепт, возвращает один `ArrayMesh` с вершинными цветами:

- фаска по рёбрам, перекосы и сужения из параметров блока;
- сфера из малого числа сегментов (низкополигональная);
- градиент цвета сверху вниз внутри блока;
- детерминированный результат: два вызова с одним рецептом дают одинаковые массивы вершин.

Материал: `StandardMaterial3D`, `vertex_color_use_as_albedo`, матовый (`roughness` около 1, без `metallic`), один на зверя и кэшируется.

### 3. Подключение в `ModelLoader`

Порядок в `get_animal`: `.glb` (если файл есть) → рецепт → существующая заглушка. Зверь без рецепта и без файла показывается заглушкой, как сейчас, без ошибки.

### 4. Анимация всего тела (режим А)

`AnimalView` получает простую анимацию кодом по типу `move` из рецепта. Анимируется корень модели (дочерний узел внутри `AnimalView`), не меняя `global_position` и логику `run_to`/`eat`:

- `hop`: подпрыгивание с лёгким сжатием и растяжением;
- `waddle`: покачивание с боку на бок и лёгкий подскок;
- `trot`: небольшая вертикальная качка и наклон вперёд;
- `idle`: лёгкое «дыхание»;
- `slither` и `swim` для змей и воды допустимы только если нужны зверям этой задачи; иначе оставить на T24e.

Анимация включена, пока зверь бежит, и спокойная в состоянии покоя. В `_process` нет создания объектов.

### 5. Звери Леса

Рецепты для 8 зверей Леса: `frog`, `rabbit`, `squirrel`, `fox`, `deer`, `boar`, `wolf`, `bear`. Каждый узнаваем по силуэту (проверка: чёрный силуэт на светлом фоне), цвета из палитры вида, различимы с игровой камеры.

### 6. Отладочная сцена «зоопарк»

Отдельная сцена `scenes/debug/zoo.tscn` и скрипт `scripts/debug/zoo.gd`, запускается из редактора («Запустить текущую сцену»). Не менять `main.gd`:

- звери с рецептами стоят рядами на земле, камера похожа на игровую (дистанция и угол как в игре);
- клавиши: переключение варианта (0–5), ступени размера, типа покоя/бега, режима «силуэт» (все материалы чёрные на светлом фоне);
- подписи только `id` зверей (латиница); локализованный текст не нужен.

Сцена нужна для того, чтобы пользователь мог быстро смотреть зверей и присылать скриншоты. В релиз она не должна влиять на размер больше, чем несколько килобайт.

## Тесты (в `tests/run_tests.gd`)

Добавить проверки для всех зверей с рецептами, не ослабляя существующие:

1. рецепт есть для 8 зверей Леса и полностью разобран без ошибок;
2. число треугольников не больше жёсткого лимита R8 (3000, для рангов 7–8 до 5000);
3. детерминизм: два построения дают одинаковые массивы вершин;
4. основание на земле: после нормализации минимальная высота модели равна 0 с допуском;
5. направление взгляда -Z: центр группы `head` не дальше от -Z, чем центр группы `body`, кроме явно отмеченных исключений в рецепте;
6. звери без рецепта по-прежнему получают заглушку;
7. все пять вариантов строятся без ошибок.

В тестах с `-s` автозагрузки брать из дерева (как уже сделано в `WorldBuilder` и `AnimalView`).

## Тебе проверить

1. Открой `scenes/debug/zoo.tscn` и посмотри каждого зверя Леса: развёрнут мордой вперёд, стоит на земле, нормального размера, силуэты различаются.
2. Режим «силуэт»: каждого видно по контуру, нет двух похожих.
3. Чек-лист R8 5.4: не похоже на Roblox (нет шипов, глянца, обводки, идеальных кубов).
4. Все пять вариантов (золото и др.) выглядят нормально.
5. В игре: бросок, приход зверя, экран получения, загон, прогулки работают как раньше; анимация не дёргает позицию.
6. Оцени плавность на своей машине (на телефоне проверяется отдельно, пришли скриншоты или описание проблемных мест).
